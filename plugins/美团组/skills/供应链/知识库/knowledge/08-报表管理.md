## 1. 模块概述

### 1.1 功能定位

**报表管理**模块是美团供应链管理系统(SCM)的核心数据分析与决策支持中心,负责:

- **数据汇总**: 整合采购、配送、库存、财务、销售等全业务链数据
- **多维分析**: 提供时间、空间、品类、供应商等多维度数据透视
- **智能洞察**: 通过数据可视化和趋势分析,支持经营决策
- **合规追溯**: 满足财务审计、质量追溯、成本核算等监管需求
- **效率提升**: 自动化报表生成,替代传统人工Excel统计

### 1.2 业务价值

#### 对总部/配送中心
- **经营分析**: 实时掌握配送金额、订货趋势、库存周转等核心指标
- **成本管控**: 监控采购成本、配送成本、损耗率等成本指标
- **绩效评估**: 评估供应商表现、配送及时率、门店订货频率等

#### 对门店
- **进销存报表**: 清晰了解商品进货、销售、库存状态
- **成本分析**: 追踪菜品成本率、毛利率等经营指标
- **采购决策**: 基于销售数据和库存预警,优化采购计划

#### 对财务部门
- **财务核算**: 生成应收应付、资金流水、成本核算等财务报表
- **对账支持**: 提供与供应商、门店的对账依据
- **税务合规**: 支持增值税发票管理、税务申报数据导出

4. **数据呈现**: 通过报表、图表、仪表盘等形式可视化展示
5. **数据导出**: 支持Excel/PDF/CSV等格式,供线下分析和存档

## 3. 核心功能详解

### 3.1 采购报表 (#menucode_1921)

#### 3.1.1 采购订单明细表

**功能说明**:
记录所有采购订单的完整交易信息,包括订单号、供应商、物品清单、数量、单价、金额、订单状态等。

**主要字段**:
- 订单信息: 订单号、下单日期、期望到货日期、实际到货日期
- 供应商信息: 供应商名称、供应商编码、联系人、联系电话
- 物品信息: 物品名称、规格、单位、数量、单价、金额
- 状态信息: 订单状态(待审核/已审核/已发货/已收货/已完成/已取消)
- 财务信息: 含税金额、税率、税额、结算状态

**业务用途**:
- 采购执行跟踪: 监控订单履行进度,及时发现延期风险
- 供应商对账: 与供应商核对订单明细,确保账实相符
- 成本分析: 统计采购金额,分析采购成本结构
- 审计追溯: 提供完整的采购交易记录,满足审计要求

**数据来源**: 采购管理模块 - 采购订单表 (purchase_orders)

#### 3.1.2 采购汇总表(按供应商)

**功能说明**:
按供应商维度汇总采购数据,展示各供应商的采购金额、订单数量、平均单价、结算周期等。

**统计维度**:
- 供应商基本信息: 供应商名称、编码、分类(蔬菜/肉类/调料等)
- 采购规模: 采购总金额、订单总数、平均单价、采购频次
- 财务数据: 已结算金额、未结算金额、账期、逾期金额
- 绩效指标: 准时交货率、质量合格率、价格稳定性、服务满意度

**业务用途**:
- 供应商评估: 识别优质供应商和问题供应商
- 采购集中度分析: 评估供应链风险,避免过度依赖单一供应商
- 议价支持: 基于采购规模,与供应商谈判价格优惠
- 供应商优化: 淘汰低效供应商,引入新供应商

**典型查询场景**:
```
查询2024年Q4采购金额TOP10供应商,按采购金额降序排列
筛选条件: 订单日期 >= 2024-10-01 AND 订单日期 <= 2024-12-31
分组字段: 供应商名称
汇总指标: SUM(采购金额), COUNT(订单数), AVG(单价)
排序规则: 采购金额 DESC
显示数量: TOP 10
```

#### 3.1.3 采购价格变动表

**功能说明**:
追踪关键物品的采购价格历史变化,帮助识别价格波动趋势和异常涨价。

**核心字段**:
- 物品信息: 物品名称、规格、单位、物品分类
- 价格数据: 当前价格、上期价格、价格变动额、变动率(%)
- 时间维度: 变动日期、统计周期(日/周/月)
- 供应商信息: 价格变动对应的供应商

**业务用途**:
- 成本预警: 及时发现异常涨价,采取应对措施(换供应商/调整菜价)
- 价格对标: 横向对比不同供应商的同一物品价格,选择最优价格
- 预算管理: 根据价格趋势,预测未来采购成本,优化预算编制
- 合同谈判: 基于历史价格数据,与供应商协商合理价格

**价格变动分析示例**:
```
物品: 五花肉
规格: 1kg
供应商A: 2024-10-01 单价28元 → 2024-11-01 单价32元 (涨幅+14.3%)
供应商B: 2024-10-01 单价27元 → 2024-11-01 单价29元 (涨幅+7.4%)

分析建议:
- 供应商A涨价幅度过大,建议转向供应商B采购
- 若因市场行情整体上涨(如生猪价格上涨),建议:
  1. 调整菜品售价,转嫁成本
  2. 优化菜单,降低五花肉使用量
  3. 寻找替代品(如精肉)
```

#### 3.1.4 供应商绩效分析表

**功能说明**:
多维度评估供应商表现,支持供应商分级管理和优化决策。

**评估维度**:
1. **交付绩效**
   - 准时交货率 = (准时交货次数 / 总交货次数) × 100%
   - 订单完成率 = (完成订单数 / 总订单数) × 100%
   - 平均交货周期(天)

2. **质量绩效**
   - 质量合格率 = (合格批次 / 总批次) × 100%
   - 退货率 = (退货金额 / 采购金额) × 100%
   - 质量问题响应时效(小时)

3. **价格绩效**
   - 价格竞争力指数(与市场均价对比)
   - 价格稳定性系数(价格波动标准差)
   - 账期支持(现款现货/月结30天/月结60天)

4. **服务绩效**
   - 服务响应速度(接单速度、问题处理速度)
   - 沟通配合度(主观评分1-5分)
   - 应急保障能力(缺货时的替代方案)

**绩效等级划分**:
- **S级供应商** (优秀): 综合评分90分以上,优先采购,长期合作
- **A级供应商** (良好): 综合评分80-89分,主力采购,稳定合作
- **B级供应商** (合格): 综合评分70-79分,补充采购,持续观察
- **C级供应商** (待改进): 综合评分60-69分,限制采购,要求整改
- **D级供应商** (淘汰): 综合评分<60分,停止合作,寻找替代

### 3.2 配送报表 (#menucode_1922)

#### 3.2.1 配送单明细表

**功能说明**:
记录配送中心向门店发货的所有配送单详情,包括配送单号、门店、物品清单、配送数量、配送状态等。

**主要字段**:
- 配送单信息: 配送单号、配送日期、配送时段(早市/晚市)
- 门店信息: 门店名称、门店编码、收货地址、收货人、联系电话
- 物品信息: 物品名称、规格、单位、计划数量、实际数量、差异数量
- 状态信息: 配送单状态(待发货/已发货/配送中/已签收/已完成)
- 财务信息: 配送金额、结算状态、结算时间

**业务用途**:
- 配送执行跟踪: 实时掌握配送进度,确保及时送达
- 配送差异分析: 对比计划数量与实际数量,分析差异原因(缺货/损耗/门店拒收)
- 门店对账: 与门店核对配送明细,确保账实相符
- 物流成本核算: 统计配送车次、配送距离,计算配送成本

**配送状态流转**:
```
待发货 → 已发货 → 配送中 → 已签收 → 已完成
   ↓         ↓         ↓         ↓
(可取消)   (可退回)  (可联系)  (可申诉)
```

#### 3.2.2 配送及时率统计表

**功能说明**:
统计配送中心的准时送达率,评估配送服务水平。

**核心指标**:
- **配送及时率** = (准时送达次数 / 总配送次数) × 100%
- **平均配送时长** = SUM(实际送达时间 - 发货时间) / 配送次数
- **延迟配送次数**: 超过承诺时间的配送次数
- **延迟原因分布**: 交通拥堵、配送员不足、门店不在、地址错误等

**时效标准**:
- **早市配送**: 要求次日早上8:00前送达,用于当天中午营业
- **晚市配送**: 要求当日下午16:00前送达,用于当天晚上营业
- **紧急配送**: 要求2小时内送达,用于临时缺货补货

**业务用途**:
- 服务水平监控: 确保配送及时性,提升门店满意度
- 配送资源优化: 根据高峰时段和区域,调整配送车辆和人员
- 绩效考核: 评估配送团队表现,与绩效工资挂钩
- SLA管理: 与门店签订服务水平协议(SLA),保障服务质量

#### 3.2.3 配送差异分析表

**功能说明**:
对比门店订货数量与实际配送数量的差异,分析差异原因和改进措施。

**差异类型**:
1. **数量差异**
   - 少送: 配送中心库存不足,无法满足订货需求
   - 多送: 配送员打包错误或门店订货数量录入错误
   - 无货: 供应商断货或物品下架,完全无法配送

2. **质量差异**
   - 门店拒收: 物品不新鲜、包装破损、规格不符
   - 退货: 送达后门店发现质量问题,申请退货

3. **价格差异**
   - 门店质疑价格: 配送价格与协议价格不一致
   - 促销未执行: 促销期间配送价格未调整

**差异处理流程**:
```
发现差异 → 记录原因 → 责任判定 → 补救措施 → 数据归档
    ↓          ↓          ↓          ↓          ↓
(门店/配送)  (系统备注)  (扣款/补货)  (调整库存)  (报表统计)
```

**改进措施**:
- 加强库存预警,提前采购高需求物品
- 优化打包流程,减少人为错误
- 加强质量检验,拒收不合格供应商货物
- 建立价格同步机制,确保价格一致性

### 3.3 库存报表 (#menucode_1923)

#### 3.3.1 实时库存查询表

**功能说明**:
提供当前时刻的库存余额查询,支持按物品、仓库、批次等维度实时查询。

**核心字段**:
- 物品信息: 物品名称、规格、单位、物品分类
- 库存数据: 当前库存数量、可用库存、预留库存、在途库存
- 仓库信息: 仓库名称、仓库类型(原料仓/半成品仓/成品仓)
- 成本信息: 单位成本、库存总成本
- 预警状态: 正常/低于下限/高于上限/呆滞

**查询方式**:
- 按物品查询: 输入物品名称或编码,查看该物品在所有仓库的库存
- 按仓库查询: 选择仓库,查看该仓库的所有物品库存
- 按分类查询: 选择物品分类(如蔬菜类/肉类),查看该分类的库存
- 按预警状态查询: 筛选低于下限或高于上限的物品,进行预警处理

**业务用途**:
- 采购决策: 根据库存余额,决定是否需要采购
- 配送决策: 根据库存余额,判断能否满足门店订货
- 盘点准备: 盘点前打印库存报表,作为盘点依据
- 成本核算: 统计库存总成本,用于财务核算

#### 3.3.2 库存周转率分析

**功能说明**:
计算物品的库存周转率,评估库存管理效率和资金占用情况。

**核心指标**:
- **库存周转率** = 销售成本 / 平均库存成本
- **库存周转天数** = 365天 / 库存周转率
- **平均库存成本** = (期初库存成本 + 期末库存成本) / 2

**周转率标准**:
- **高周转物品** (周转率>12次/年,周转天数<30天): 生鲜蔬菜、鲜肉等
- **中周转物品** (周转率6-12次/年,周转天数30-60天): 调料、干货等
- **低周转物品** (周转率<6次/年,周转天数>60天): 设备、包装材料等

**业务用途**:
- 库存优化: 对低周转物品减少采购量,释放资金
- 滞销识别: 周转天数超过90天的物品,视为滞销品,考虑促销或淘汰
- 绩效评估: 库存周转率是衡量供应链管理水平的重要KPI
- 资金规划: 高周转物品占用资金少,可优先采购

#### 3.3.3 呆滞库存分析表

**功能说明**:
识别长期无销售、库存积压的呆滞物品,避免资金占用和物品变质。

**呆滞标准**:
- **呆滞库存** = 超过X天无出库记录的库存(X通常为60-90天)
- **滞销物品** = 近Y个月销售量低于平均值50%的物品(Y通常为3-6个月)

**呆滞分析维度**:
- 呆滞天数: 最后出库日期至今的天数
- 呆滞金额: 呆滞库存数量 × 单位成本
- 呆滞原因: 季节性、菜品下架、采购过量、质量问题等
- 处置建议: 促销、退货、报废、捐赠等

**处置流程**:
```
识别呆滞 → 原因分析 → 处置方案 → 审批执行 → 库存调整
    ↓          ↓          ↓          ↓          ↓
(系统自动)  (人工判断)  (促销/报废)  (领导签字)  (账务处理)
```

**预防措施**:
- 建立安全库存模型,避免采购过量
- 加强销售预测,提前识别滞销风险
- 灵活调整菜单,消耗呆滞原料
- 与供应商协商退货政策,降低呆滞损失

### 3.4 财务报表 (#menucode_1924)

#### 3.4.1 应收应付汇总表

**功能说明**:
汇总配送中心与门店、供应商之间的应收应付款项,支持财务对账和资金管理。

**应收账款**(配送中心应向门店收取的款项):
- 应收总额: 已配送但未结算的金额
- 已收金额: 门店已支付的金额
- 未收金额: 应收总额 - 已收金额
- 逾期金额: 超过账期未支付的金额
- 账龄分析: 0-30天、31-60天、61-90天、>90天

**应付账款**(配送中心应向供应商支付的款项):
- 应付总额: 已采购但未结算的金额
- 已付金额: 已向供应商支付的金额
- 未付金额: 应付总额 - 已付金额
- 逾期金额: 超过账期未支付的金额

**业务用途**:
- 资金预测: 预估未来需要收款和付款的金额,规划资金流
- 催款管理: 识别逾期未付款的门店,进行催款
- 付款计划: 合理安排向供应商付款的时间和金额
- 财务分析: 分析应收应付比例,评估资金占用情况

#### 3.4.2 成本核算表

**功能说明**:
核算物品的采购成本、加工成本、配送成本等,支持成本分析和价格制定。

**成本构成**:
1. **采购成本**: 向供应商采购的原价(含税或不含税)
2. **运输成本**: 供应商送货到配送中心的运费
3. **损耗成本**: 验收、储存、配送过程中的损耗
4. **加工成本**: 半成品加工的人工、水电、设备折旧等
5. **配送成本**: 配送中心送货到门店的运费、人工等
6. **管理成本**: 仓库管理、质检、系统维护等间接成本

**成本计算公式**:
```
单位总成本 = 采购成本 + 运输成本 + 损耗成本 + 加工成本 + 配送成本 + 管理成本摊销

毛利 = 销售价格 - 单位总成本
毛利率 = (毛利 / 销售价格) × 100%
```

**业务用途**:
- 定价决策: 基于成本,制定合理的配送价格,确保盈利
- 成本控制: 识别高成本环节,采取降本措施
- 盈利分析: 计算每个物品的毛利率,优化物品结构
- 绩效考核: 评估采购、仓储、配送等环节的成本控制能力

#### 3.4.3 毛利分析表

**功能说明**:
分析不同物品、门店、时间段的毛利率,优化商品结构和经营策略。

**分析维度**:
- **按物品分析**: 识别高毛利和低毛利物品,调整采购和销售策略
- **按门店分析**: 对比不同门店的毛利率,评估门店经营能力
- **按时间分析**: 分析毛利率的月度、季度、年度变化趋势
- **按分类分析**: 对比蔬菜类、肉类、调料类等不同分类的毛利率

**毛利优化策略**:
- **高毛利物品**: 加大采购和推广力度,提升销售占比
- **低毛利物品**: 降低采购成本(换供应商/集中采购)或提升售价
- **负毛利物品**: 停止采购,下架菜品,避免亏损
- **毛利波动物品**: 分析原因(成本波动/促销活动),采取稳定措施

### 3.5 销售报表 (#menucode_1925)

#### 3.5.1 门店销售汇总表

**功能说明**:
按门店维度汇总销售数据,评估门店经营业绩。

**核心指标**:
- 销售金额: 门店总营业额
- 销售数量: 销售的商品总数量
- 客单价: 销售金额 / 订单数
- 客流量: 门店接待的顾客总数
- 成交率: 成交订单数 / 总客流量
- 复购率: 复购客户数 / 总客户数

**业务用途**:
- 业绩排名: 对比各门店销售金额,评选优秀门店
- 异常识别: 识别销售异常波动的门店,分析原因
- 资源分配: 根据销售业绩,分配促销资源和库存资源
- 选址评估: 分析新门店的销售业绩,评估选址成功率

#### 3.5.2 商品销售排行榜

**功能说明**:
统计销售金额或销售数量TOP N的商品,识别畅销品和滞销品。

**排行维度**:
- **销售金额排行**: 按销售金额降序排列,识别贡献最大的商品
- **销售数量排行**: 按销售数量降序排列,识别销售最广的商品
- **毛利排行**: 按毛利额降序排列,识别利润最高的商品
- **增长率排行**: 按同比/环比增长率排列,识别增长最快的商品

**业务用途**:
- 菜单优化: 保留畅销品,淘汰滞销品,优化菜单结构
- 采购计划: 加大畅销品采购量,减少滞销品采购量
- 促销策略: 对滞销品进行促销,提升销售
- 新品开发: 基于畅销品特征,开发类似新品

#### 3.5.3 菜品成本率分析

**功能说明**:
计算每道菜品的成本率,评估菜品定价合理性。

**成本率公式**:
```
菜品成本率 = (菜品原材料成本 / 菜品售价) × 100%
```

**成本率标准**:
- **正常范围**: 30%-40% (餐饮行业平均水平)
- **高成本菜品**: >40% (需优化配方或提价)
- **低成本菜品**: <30% (可适当降价促销)

**业务用途**:
- 定价优化: 调整成本率过高或过低的菜品价格
- 配方优化: 优化高成本菜品的原材料配方,降低成本
- 菜单设计: 搭配不同成本率的菜品,整体控制成本率在35%左右
- 利润预测: 基于成本率,预测菜品和门店的整体利润

### 3.6 生产报表 (#menucode_1926)

#### 3.6.1 生产计划执行表

**功能说明**:
跟踪生产计划的执行情况,评估生产效率和完成率。

**核心字段**:
- 生产计划: 计划生产数量、计划完成时间
- 生产实绩: 实际生产数量、实际完成时间
- 差异分析: 数量差异、时间差异、差异原因
- 完成率: (实际生产数量 / 计划生产数量) × 100%

**业务用途**:
- 生产调度: 根据计划执行情况,调整生产排期
- 异常处理: 识别生产延误,及时采取补救措施
- 绩效考核: 评估生产团队的执行能力
- 计划优化: 基于历史数据,优化未来生产计划的准确性

#### 3.6.2 生产成本分析表

**功能说明**:
核算半成品和成品的生产成本,支持成本控制和价格制定。

**成本构成**:
- **直接材料成本**: 生产使用的原材料成本
- **直接人工成本**: 生产人员的工资
- **制造费用**: 水电、设备折旧、场地租金等间接成本

**成本计算**:
```
单位生产成本 = (直接材料成本 + 直接人工成本 + 制造费用) / 生产数量
```

**业务用途**:
- 定价依据: 基于生产成本,制定半成品/成品价格
- 成本控制: 识别成本过高的环节,采取降本措施
- 外包决策: 对比自产成本与外购成本,决定是否外包
- 工艺优化: 优化生产工艺,提升生产效率,降低成本

### 3.7 质量报表 (#menucode_1927)

#### 3.7.1 质检明细表

**功能说明**:
记录所有质检活动的详细信息,包括质检批次、质检结果、不合格项等。

**核心字段**:
- 质检信息: 质检单号、质检日期、质检人、质检类型(进货检验/过程检验/成品检验)
- 被检物品: 物品名称、批次号、供应商、数量
- 质检结果: 合格/不合格、不合格原因、不合格数量
- 处理措施: 退货/返工/报废/特采(特殊采购,允许使用)

**业务用途**:
- 质量追溯: 通过批次号,追溯质量问题的源头
- 供应商评估: 统计供应商的质检合格率,评估供应商质量水平
- 质量改进: 分析不合格原因,改进质检标准和采购标准
- 合规证明: 提供质检记录,满足食品安全监管要求

#### 3.7.2 供应商质量评分

**功能说明**:
基于质检数据,对供应商进行质量评分,支持供应商分级管理。

**评分维度**:
- **合格率** = (合格批次 / 总批次) × 100% (权重40%)
- **响应速度**: 质量问题反馈后的处理速度(权重20%)
- **改进能力**: 质量问题的重复发生率(权重20%)
- **文档完整性**: 质检报告、检疫证明等文档的齐全性(权重20%)

**评分等级**:
- **A级供应商** (90分以上): 质量可靠,免检或抽检
- **B级供应商** (80-89分): 质量良好,正常检验
- **C级供应商** (70-79分): 质量一般,加强检验
- **D级供应商** (<70分): 质量问题频发,限制采购或淘汰

**业务用途**:
- 供应商准入: 新供应商需达到B级以上才能长期合作
- 供应商淘汰: 连续3个月低于C级的供应商,考虑淘汰
- 免检政策: A级供应商可申请免检,降低质检成本
- 价格谈判: 质量高的供应商可适当接受高价,质量低的供应商要求降价

### 3.8 效期管理报表 (#menucode_1928)

#### 3.8.1 临期商品预警表

**功能说明**:
识别即将过期的商品,提前采取处理措施,避免损失。

**预警标准**:
- **一级预警**(红色): 距离过期≤3天,需立即处理(促销/报废)
- **二级预警**(橙色): 距离过期4-7天,需加快使用(优先配送/调拨)
- **三级预警**(黄色): 距离过期8-15天,需关注监控

**核心字段**:
- 物品信息: 物品名称、批次号、生产日期、保质期、到期日期
- 库存信息: 当前库存数量、库存位置
- 预警级别: 一级/二级/三级
- 处理建议: 促销/调拨/报废/捐赠

**业务用途**:
- 损失预防: 提前处理临期商品,避免过期报废损失
- 先进先出: 确保先采购的商品先使用,减少临期风险
- 促销决策: 对临期商品进行折扣促销,快速消化库存
- 采购优化: 控制采购量,避免库存积压导致临期

#### 3.8.2 损耗原因分析

**功能说明**:
分析商品损耗的原因和金额,支持损耗控制和改进措施。

**损耗分类**:
1. **自然损耗**: 蔬菜脱水、水果腐烂等自然损耗(正常范围)
2. **过期损耗**: 超过保质期报废(需控制采购量)
3. **质量损耗**: 质量不合格退货或报废(需提升供应商质量)
4. **人为损耗**: 搬运、包装、配送中的人为破损(需加强培训)
5. **盘点损耗**: 盘点发现的实物短缺(需排查盗窃和账务错误)

**损耗率计算**:
```
损耗率 = (损耗金额 / 采购金额) × 100%
```

**业务用途**:
- 损耗控制: 设定损耗率上限(如2%),超出则分析原因
- 责任追究: 对人为损耗进行责任判定和处罚
- 流程优化: 优化搬运、储存、配送流程,降低损耗
- 保险索赔: 对大额损耗(如火灾、水灾),向保险公司索赔

## 6. 报表生成流程

### 6.1 自动报表生成流程

```
数据采集 → 数据清洗 → 数据计算 → 报表渲染 → 报表发布 → 报表归档
    ↓          ↓          ↓          ↓          ↓          ↓
(实时抓取)  (去重校验)  (指标计算)  (模板填充)  (推送通知)  (历史存档)
```

**详细步骤**:

1. **数据采集** (每小时/每天定时触发)
   - 从业务数据库(MySQL/PostgreSQL)读取原始交易数据
   - 数据源: 采购订单表、配送单表、库存流水表、销售订单表等
   - 采集方式: SQL查询 + ETL工具(Extract-Transform-Load)

2. **数据清洗** (数据质量保障)
   - 去重: 删除重复记录(基于唯一键:订单号、配送单号等)
   - 校验: 检查数据完整性(非空字段、数值范围、日期格式)
   - 关联: 关联主数据(物品、门店、供应商等)
   - 异常处理: 标记异常数据,记录错误日志

3. **数据计算** (业务逻辑执行)
   - 汇总计算: GROUP BY + SUM/AVG/COUNT等聚合函数
   - 指标计算: 周转率、合格率、增长率等衍生指标
   - 排名计算: ROW_NUMBER() / RANK() 窗口函数
   - 同比环比: 与历史数据对比计算增长率

4. **报表渲染** (可视化呈现)
   - 模板填充: 将计算结果填入预定义的报表模板(Excel/HTML)
   - 图表生成: 生成柱状图、折线图、饼图等可视化图表
   - 样式美化: 应用颜色、字体、边框等样式
   - 分页处理: 超大报表自动分页

5. **报表发布** (用户访问)
   - Web展示: 在报表管理界面展示,支持在线查看
   - 邮件推送: 自动发送报表到指定邮箱(每日晨报)
   - 微信推送: 通过企业微信/钉钉推送报表摘要
   - 下载导出: 支持Excel/PDF/CSV格式下载

6. **报表归档** (历史数据管理)
   - 数据库存储: 将报表数据存入历史表,保留3-5年
   - 文件归档: 将报表文件存入文件服务器或云存储
   - 定期清理: 超过保留期的数据自动归档或删除

### 6.2 手动报表生成流程

```
用户登录 → 选择报表 → 设置参数 → 点击生成 → 等待计算 → 查看结果 → 导出下载
    ↓          ↓          ↓          ↓          ↓          ↓          ↓
(权限验证)  (报表类型)  (筛选条件)  (提交请求)  (异步计算)  (在线预览)  (文件下载)
```

**详细步骤**:

1. **用户登录** (权限验证)
   - 输入账号密码,系统验证身份
   - 检查用户角色,确定可访问的报表范围
   - 记录登录日志,用于审计追溯

2. **选择报表** (报表目录)
   - 从报表分类(采购/配送/库存等)选择所需报表
   - 查看报表说明,了解报表用途和字段含义
   - 选择报表版本(标准版/明细版/汇总版)

3. **设置参数** (筛选条件)
   - 时间范围: 起始日期、结束日期
   - 组织维度: 配送中心、门店、仓库
   - 数据维度: 供应商、物品分类、物品
   - 其他条件: 订单状态、配送方式、结算状态等

4. **点击生成** (提交请求)
   - 前端验证参数合法性(日期不能为空、起始日期≤结束日期)
   - 提交请求到后端API
   - 后端接收请求,生成任务ID,返回给前端

5. **等待计算** (异步处理)
   - 前端轮询任务状态(每2秒查询一次)
   - 后端执行SQL查询,计算报表数据
   - 显示进度条: 数据采集(30%) → 数据计算(60%) → 报表渲染(90%) → 完成(100%)

6. **查看结果** (在线预览)
   - 报表生成完成后,前端跳转到预览页面
   - 支持表格视图、图表视图、透视视图
   - 支持排序、筛选、搜索、分页等交互

7. **导出下载** (文件生成)
   - 点击导出按钮,选择导出格式(Excel/PDF/CSV)
   - 后端生成文件,返回下载链接
   - 前端触发浏览器下载,保存到本地

### 6.3 定时报表调度流程

**调度工具**: Cron / Quartz / Airflow

**典型调度配置**:
```
日报: 每天凌晨02:00执行,统计昨日数据
周报: 每周一早上06:00执行,统计上周数据
月报: 每月1日早上06:00执行,统计上月数据
实时报表: 每小时00分执行,统计过去1小时数据
```

**调度流程**:
```
触发时间到达 → 检查任务状态 → 执行报表生成 → 发送通知 → 记录日志
       ↓              ↓              ↓              ↓           ↓
   (Cron触发)     (避免重复)      (自动生成)      (邮件/微信)  (成功/失败)
```

**异常处理**:
- 任务超时: 超过30分钟未完成,自动终止任务,发送告警
- 任务失败: 记录错误日志,发送告警通知管理员
- 数据异常: 检测到异常数据(如负数销售额),标记异常,暂停推送
- 重试机制: 失败后自动重试3次,间隔5分钟

```python
# 基于销售趋势和库存状态,自动生成采购建议
def generate_purchase_recommendation(sales_data, inventory_data):
    recommendations = []

    for item in inventory_data:
        # 计算平均日销量
        avg_daily_sales = sales_data[item['name']]['avg_daily_sales']

        # 计算安全库存天数(7天销量)
        safety_stock_days = 7
        safety_stock = avg_daily_sales * safety_stock_days

        # 计算采购量
        current_stock = item['quantity']
        if current_stock < safety_stock:
            purchase_qty = safety_stock * 2 - current_stock  # 补足至14天销量
            recommendations.append({
                'item_name': item['name'],
                'current_stock': current_stock,
                'safety_stock': safety_stock,
                'purchase_qty': purchase_qty,
                'reason': f'库存低于安全库存,建议采购{purchase_qty}{item["unit"]}'
            })

    return recommendations
```

```python
# 检测采购价格异常波动
def detect_price_anomaly(price_history):
    anomalies = []

    for item, prices in price_history.items():
        # 计算过去30天平均价格
        avg_price = sum(prices) / len(prices)
        std_price = statistics.stdev(prices)

        # 检测最新价格是否超过2个标准差
        latest_price = prices[-1]
        if abs(latest_price - avg_price) > 2 * std_price:
            anomalies.append({
                'item_name': item,
                'avg_price': avg_price,
                'latest_price': latest_price,
                'deviation': ((latest_price - avg_price) / avg_price) * 100,
                'alert_level': 'high' if abs(latest_price - avg_price) > 3 * std_price else 'medium'
            })

    return anomalies
```

## 11. 常见问题与解决方案

### 11.1 报表生成问题

**问题1: 报表生成超时**
- 现象: 点击生成报表后,长时间无响应
- 原因: 数据量过大,SQL查询超时
- 解决方案:
  1. 缩小时间范围(如从全年改为单月)
  2. 减少筛选条件(如只查询特定门店)
  3. 联系技术支持优化SQL查询性能

**问题2: 报表数据不准确**
- 现象: 报表数据与实际业务不符
- 原因: 数据同步延迟、计算逻辑错误、权限问题
- 解决方案:
  1. 等待5-10分钟,数据同步完成后重新生成
  2. 对比明细数据,检查汇总逻辑是否正确
  3. 确认账号权限,是否能查看全部数据

**问题3: 导出报表失败**
- 现象: 点击导出后,提示"导出失败"
- 原因: 文件过大、浏览器限制、网络问题
- 解决方案:
  1. 分批导出(如按月导出,而非全年)
  2. 更换浏览器(推荐Chrome/Edge)
  3. 检查网络连接,重试导出

### 11.2 数据理解问题

**问题4: 如何理解"库存周转率"**
- 概念: 库存周转率 = 销售成本 / 平均库存成本
- 意义: 库存周转率越高,说明库存周转越快,资金占用越少
- 示例: 周转率12次/年 = 365天/12 = 30天周转一次
- 优化建议: 提升周转率方法:
  1. 减少采购量,降低库存水平
  2. 加快销售,提升销售成本
  3. 淘汰滞销品,聚焦畅销品

**问题5: 如何理解"毛利率"**
- 概念: 毛利率 = (销售价格 - 成本) / 销售价格 × 100%
- 意义: 毛利率越高,盈利能力越强
- 示例: 菜品售价100元,成本40元,毛利率=(100-40)/100=60%
- 优化建议: 提升毛利率方法:
  1. 提高售价(但需考虑市场接受度)
  2. 降低成本(优化供应商、减少损耗)
  3. 优化菜单结构(保留高毛利菜品)

### 11.3 操作使用问题

**问题6: 如何订阅报表推送**
- 步骤:
  1. 进入报表管理 → 报表配置 → 报表订阅
  2. 选择需要订阅的报表类型
  3. 设置推送频率(每日/每周/每月)
  4. 选择推送渠道(邮件/微信)
  5. 保存订阅设置
- 注意事项:
  - 邮件推送需提前配置邮箱
  - 微信推送需关注企业微信公众号

**问题7: 如何自定义报表**
- 步骤:
  1. 进入报表管理 → 综合分析报表 → 自定义报表生成器
  2. 选择数据源(采购/配送/库存等)
  3. 选择维度(时间/门店/物品等)
  4. 选择指标(销售额/数量/毛利率等)
  5. 设置筛选条件和排序规则
  6. 预览报表,保存为模板
- 高级功能:
  - 支持多表关联查询
  - 支持自定义计算字段
  - 支持数据透视和交叉分析

## 12. 系统优化建议

### 12.1 报表性能优化

**优化1: 数据分层存储**
- 明细数据: 保留近3个月,超过3个月归档到历史库
- 汇总数据: 每日/每周/每月自动汇总,存入汇总表
- 指标数据: 预计算常用指标(如周转率、毛利率),存入指标表
- 效果: 查询速度提升80%, 减少实时计算压力

**优化2: 索引优化**
- 为常用查询字段建立索引(如: 订单号、日期、门店ID、物品ID)
- 使用复合索引(如: 日期 + 门店ID)
- 定期重建索引,提升查询效率

**优化3: 缓存机制**
- 对热点报表(如经营数据驾驶舱)进行缓存,5分钟刷新一次
- 对静态数据(如供应商列表、物品列表)进行缓存,24小时刷新一次
- 使用Redis缓存,提升响应速度

### 12.2 用户体验优化

**优化5: 报表可视化增强**

**优化6: 移动端适配**
- 开发移动端报表App,支持手机查看
- 优化报表排版,适配小屏幕
- 支持微信小程序,随时随地查看报表

### 12.3 数据质量优化

**优化7: 数据校验机制**
- 入库前校验: 检查数据格式、数值范围、必填字段
- 逻辑校验: 检查业务逻辑(如退货金额不能大于采购金额)

**优化8: 数据追溯机制**
