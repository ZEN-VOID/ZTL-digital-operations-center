# F0-需求分析师智能体重构

## 📋 功能概述

### 目标
将现有的 `F0-产品经理` 智能体重构为 **需求分析师（Requirements Analyst）**，专注于深度需求分析和高质量PRP文档生成，成为开发流程的真正Phase 0。

### 业务价值
- **提升需求质量**：通过系统化的PRP流程，确保需求分析的完整性和可执行性
- **降低开发风险**：在编码前通过深度研究和规划，减少返工和错误
- **标准化流程**：为开发组建立统一的需求分析方法论
- **提高协作效率**：输出结构化的PRP文档，作为开发团队的唯一指南

### 应用场景
- 新功能开发前的需求分析与技术规划
- 系统重构前的现状调研与方案设计
- 复杂业务逻辑的梳理与文档化
- 技术可行性评估与风险识别

### 核心功能点
1. **PRP方法论融合**：7步系统化需求分析流程
2. **13元素系统提示**：符合2025最佳实践的智能体架构
3. **双模式运行**：独立模式（交互式）和批量模式（自动化）
4. **研究驱动**：代码库分析 + 外部最佳实践研究
5. **质量保证**：PRP评分 ≥8/10 的强制标准

```markdown
# F0-产品经理 (Product Manager)

## 🎯 核心职责
### 专业领域
- **需求分析**: 用户访谈、需求挖掘、痛点分析
- **产品规划**: 产品路线图、功能优先级、版本规划
...
```

**问题识别**:
1. ❌ 职责过于宽泛（产品规划 + 需求分析 + UX设计）
2. ❌ 缺少Task Mode定义（独立模式 vs 批量模式）
3. ❌ 缺少Skills依赖声明
4. ❌ description字段缺少丰富的触发示例
5. ❌ 工具配置缺少研究工具（WebSearch, WebFetch）
6. ❌ 没有融入PRP方法论

### 技术陷阱

**智能体设计陷阱**:
- ⚠️ **职责模糊陷阱**: 智能体职责过多会导致自动委派失效
- ⚠️ **描述字段陷阱**: description过于简单会导致Claude无法正确识别何时调用
- ⚠️ **工具配置陷阱**: 工具过少会限制智能体能力，工具过多会分散注意力
- ⚠️ **示例缺失陷阱**: 没有丰富的<example>会导致智能体行为不可预测

**PRP流程陷阱**:
- ⚠️ **研究深度陷阱**: 研究不足会导致PRP评分低于8分
- ⚠️ **验证门控陷阱**: 验证命令必须可由AI自动执行，不能依赖人工
- ⚠️ **模板机械填充陷阱**: 必须深度思考而非机械填充模板

### 伪代码设计 - 核心工作流

```python
# Phase 1: 需求理解
def understand_requirements(input: str) -> RequirementContext:
    """
    理解功能需求和上下文

    PATTERN: 首先识别输入类型
    - 文件路径 → 读取文件内容
    - 描述文本 → 直接分析
    """
    if is_file_path(input):
        content = Read(input)
    else:
        content = input

    # CRITICAL: 提取关键成功标准
    context = {
        "core_features": extract_features(content),
        "business_value": identify_value(content),
        "technical_constraints": identify_constraints(content),
        "success_criteria": extract_criteria(content)
    }

    return context


# Phase 2: 研究分析
def research_and_analyze(context: RequirementContext) -> ResearchResult:
    """
    代码库分析 + 外部研究

    PATTERN: 分层研究策略
    - Layer 1: 代码库中的相似功能
    - Layer 2: 外部最佳实践
    - Layer 3: 技术陷阱识别
    """
    # 代码库分析
    similar_patterns = Glob("**/*.py") + Grep("class|def", pattern=context.keywords)
    existing_code = Read(similar_patterns[0:5])  # 读取前5个相关文件

    # 外部研究
    official_docs = WebSearch(f"{context.tech_stack} official documentation")
    best_practices = WebFetch(official_docs[0].url, prompt="Extract implementation patterns")

    # GOTCHA: 必须包含URL引用到PRP中
    research = {
        "codebase_patterns": extract_patterns(existing_code),
        "documentation_refs": official_docs,
        "best_practices": best_practices,
        "tech_gotchas": identify_gotchas(context.tech_stack)
    }

    return research


# Phase 3: 用户澄清
def clarify_with_user(context: RequirementContext, research: ResearchResult) -> ClarificationResult:
    """
    识别模糊需求并提问

    PATTERN: 结构化提问
    - 特定模式澄清
    - 集成要求澄清
    - 技术约束澄清
    """
    ambiguities = identify_ambiguities(context, research)

    if len(ambiguities) > 0:
        # CRITICAL: 使用结构化问题
        questions = [
            f"需要镜像哪些特定模式？参考文件: {research.codebase_patterns}",
            f"性能要求是什么？QPS预期、延迟容忍度？",
            f"安全考虑？认证方式、授权策略？"
        ]

        # 等待用户响应
        user_responses = await_user_input(questions)
        context.update(user_responses)

    return context


# Phase 4: 深度思考 ⚠️
def deep_thinking(context: RequirementContext, research: ResearchResult) -> ImplementationPlan:
    """
    关键步骤：在生成PRP前进行深度思考

    CRITICAL: 不能机械填充模板
    """
    <scratchpad>
    1. 整体架构思考:
       - 如何设计整体架构？
       - 关键技术挑战是什么？
       - 风险点在哪里？

    2. 实施路径规划:
       - 最佳实施顺序是什么？
       - 依赖关系如何？
       - 如何分阶段交付？

    3. 质量保证策略:
       - 如何确保质量？
       - 测试策略是什么？
       - 验证门控如何设计？
    </scratchpad>

    plan = {
        "architecture": design_architecture(context, research),
        "implementation_path": plan_implementation(context, research),
        "quality_strategy": design_validation(context)
    }

    return plan


# Phase 5: PRP文档生成
def generate_prp_document(
    context: RequirementContext,
    research: ResearchResult,
    plan: ImplementationPlan
) -> PRPDocument:
    """
    基于prp_base.md模板生成PRP文档

    PATTERN: 遵循模板结构
    """
    template = Read("PRPs/templates/prp_base.md")

    prp = {
        "goal": context.core_features,
        "why": context.business_value,
        "what": context.success_criteria,

        # 关键上下文
        "documentation_refs": research.documentation_refs,  # 必须包含URL
        "code_examples": research.codebase_patterns,        # file:line引用
        "tech_gotchas": research.tech_gotchas,

        # 实现蓝图
        "data_models": plan.architecture.models,
        "task_breakdown": plan.implementation_path.tasks,
        "pseudocode": plan.architecture.pseudocode,

        # 验证门控
        "validation_gates": plan.quality_strategy.gates,  # CRITICAL: 必须可AI执行

        # 输出控制
        "output_path": f"PRPs/{sanitize_filename(context.feature_name)}.md"
    }

    # GOTCHA: 验证门控必须可执行
    assert all(is_executable(gate) for gate in prp.validation_gates)

    return prp


# Phase 6: 质量评估
def evaluate_quality(prp: PRPDocument) -> QualityScore:
    """
    评估PRP质量并迭代优化

    PATTERN: 评分维度
    - 上下文完整性 (30%)
    - 实现路径清晰度 (30%)
    - 验证可执行性 (20%)
    - 错误处理完整性 (20%)
    """
    score = {
        "context_completeness": rate_context(prp),
        "path_clarity": rate_clarity(prp),
        "validation_executable": rate_validation(prp),
        "error_handling": rate_error_handling(prp)
    }

    total_score = (
        score.context_completeness * 0.3 +
        score.path_clarity * 0.3 +
        score.validation_executable * 0.2 +
        score.error_handling * 0.2
    )

    # CRITICAL: 评分<8必须重新生成
    if total_score < 8:
        # 识别短板并补充研究
        weak_areas = identify_weak_areas(score)
        additional_research = conduct_additional_research(weak_areas)

        # 重新生成
        return generate_prp_document(context, research + additional_research, plan)

    return total_score


# 主流程编排
async def execute_requirements_analysis(user_input: str) -> PRPDocument:
    """
    完整需求分析流程

    根据Task Mode自动识别执行模式:
    - Independent Mode: 交互式,需用户确认
    - Batch Mode: 自动化,无需确认
    """
    # 识别模式
    mode = detect_mode()  # "independent" or "batch"

    # Phase 1-4: 核心分析流程
    context = understand_requirements(user_input)
    research = await research_and_analyze(context)

    if mode == "independent":
        context = await clarify_with_user(context, research)

    plan = deep_thinking(context, research)

    # Phase 5-6: 文档生成与验证
    prp = generate_prp_document(context, research, plan)
    score = evaluate_quality(prp)

    # 保存文档
    Write(prp.output_path, prp.content)

    # 根据模式返回
    if mode == "independent":
        # 交互式提议
        return {
            "prp_path": prp.output_path,
            "score": score,
            "next_action": "任务完成。建议下一步: 基于PRP执行实现？使用 /E 命令开始执行"
        }
    else:
        # 批量模式直接返回
        return {
            "prp_path": prp.output_path,
            "score": score
        }
```
